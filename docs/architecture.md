# Sprout Valley 架构设计

## 数据流

`ContentCatalog` 启动时读取 `data/` 下的 JSON，检查引用、坐标、类型和素材，构建碰撞格、水域、树木、杂物、出口图和地点索引；任何一处不合格就返回错误，游戏拒绝启动。`FarmState` 保存当前进度。规则接收状态、修改它并返回 `{ok, message, ...}`，失败时状态完全不变。`game.gd` 把输入交给规则，再通知界面、画面和存档。

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| core | 配置、索引、状态、日历、设置 | 不处理输入、节点和磁盘存档 |
| gameplay | 农耕、商店、采集、烹饪、钓鱼、动物、小事、委托、天气 | 纯逻辑；无效操作不消耗体力或库存 |
| story | 主线阶段、交谈、送礼、心事件、节日、采集、换图 | 阶段和奖励同时提交，不重复领取 |
| world | 地图世界、村民日程与路线、玩家动作、特效、季节与天气表现 | 不决定任务和经济规则 |
| ui | 标题、存档位、创建角色、HUD、对话和各种面板 | 通过 `action_requested(action, payload)` 发送意图 |
| persistence | 三个存档位的 JSON 读写、入口校验、反序列化 | 只接受当前格式；不修复、不迁移、不备份 |

标题与游戏界面共用 `GameScreen` 的样式工具（框、标签、按钮、翻页、页签），各自继承。`FarmHUD` 只管常驻信息与短提示，`GameDialogs` 按需打开面板（商店、背包、烹饪、动物、告示板、图志、钓鱼、休息、收货、暂停、设置、手记、地图、村民、礼物、对话、结局）；两者通过信号协作。九宫格皮肤、图标和标题背景由 `tools/art/interface.py` 绘制。所有村民台词放在 `data/story.json`。

## 地图和镜头

每张地图一个 JSON，单位网格 32 像素。室外大地图存放背景、道路、水域、静态碰撞、树木、物件、装饰、围栏、站点、出口、出生点和采集点；农场另有建筑地块。室内地图 30×19 格，固定展示整个房间。

游戏区域通过 1280×800 的 `SubViewport` 显示，UI 位于主视口。`Camera2D` 在室外跟随角色并限制边界。世界坐标与鼠标坐标通过 `canvas_transform` 双向转换。静态阻挡按格索引，运行时合并水平连续格生成碰撞矩形；树木、建筑、角色、杂物按脚底位置排序；水域按格索引，供钓鱼判断。

## 时间与日程

`FarmState.minute` 是一天里的分钟数（360 = 06:00，上限 1560 = 26:00）。游戏每现实 7 秒推进 10 分钟，菜单暂停。`NpcPlanner` 为每个村民按当天条件（生日、节日、星期、第几周、季节、天气、年份、剧情阶段）选出第一条匹配规则，在每张地图的 `AStarGrid2D` 上用广度优先搜索出口图生成逐格路线，按到达时刻倒推出发时刻，得到一条时间线；`where(id, minute)` 返回此刻的位置、朝向、是否在走、是否在屋内、在做什么。时间线不存档，读档、换图、睡觉后都由同一函数重算，结果一致。

`FarmWorld` 根据 planner 创建村民节点（只为当天会来这张地图的人），每帧更新位置和行走帧，可见的村民成为可交谈的站点。

## 确定性

天气是“世界种子 + 日期”的函数；清晨小事、采集结果、公告栏委托也由种子、日期（加采集点或周数）决定，因此预报永远正确，存档里不需要保存它们。`game.gd` 的 `fixed_seed` 让测试固定世界种子（0 = 全年晴天）。

## 规则细节

- 工具动作：`Farmer` 与 `ToolMotion` 负责蓄力、接触和收势，接触帧发出信号，`game.gd` 执行规则一次；动作期间不能移动或开始另一个动作；菜单冻结待完成的动作。
- 钓鱼：`FishingRules` 选鱼、算等待时间和绿区；`FishingPanel` 是小游戏（等待 → 咬钩 → 计时条），结果经 `finished(fish_id)` 返回，`game.gd` 再调用规则入账。
- 商店：`ShopRules` 统一处理营业时间、买、卖、熔炼、升级、治疗；`ShopPanel` 只展示并发出动作，`game.gd` 执行后重开同一页签。
- 存档：`SaveStore` 管三个位置，写入先写 `.tmp` 再重命名；`SaveValidator` 检查每一个字段；`FarmState.from_validated` 只处理已校验的数据。
- 树木：`tree_damage` 以“地图:坐标”为键保存累计 1–5 次斧击，保存校验与开垦规则用同一份树木状态。

## 开发约定

- 数据模型和代码只有一套当前版本：没有备份、迁移入口或兼容分支。
- 外部 JSON、磁盘存档、设置文件和玩家输入在入口验证，失败时明确报错；内部关系保持简单。
- GDScript 使用 gdformat，Python 工具使用 Ruff。
- 改动规则后跑规则测试；改变完整流程、镜头或 UI 后跑窗口测试并检查截图。
- 内容与行为分开；生成工具不进入游戏运行时。

## 当前边界

室外背景是各地图烘焙的整张纹理，适合几千格规模的地图；进一步扩展到无缝超大世界时，应改为分块背景或 TileMapLayer。矿洞没有战斗；婚恋只做到第 5 段心事件，没有婚后生活；主线只有第一章。这些在 design/ 里标为扩展方向。
