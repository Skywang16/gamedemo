## 1. 体量目标

目标是“第一年内容量与一款成熟的农场角色扮演游戏相当”，用数字约束自己：

| 项目 | 现状 | 目标 |
| --- | --- | --- |
| 有名字的人物 | 4 | **30**（12 位可恋爱；其余为镇民、家人、访客） |
| 人物专属事件（“心事件”，好感达到某个数值时触发的一段剧情） | 1 段/人 | 可恋爱角色 5 段 + 婚后 2 段；其他角色 3 段 |
| 主线 | 1 章，7 阶段 | 序章 + 4 章（春夏秋冬）+ 终章，约 40 个阶段 |
| 季节与日历 | 无 | 4 季 × 28 天；9 个节日；每人一个生日 |
| 地图 | 7 张 | 约 20 张（含室内、暗渠、温室、山茶坡等） |
| 作物 | 2 | 28 种（四季各 7 种）+ 3 种树木果实 |
| 特殊事件 | 0 | 约 55 个（夜间、天气、访客、农场、小镇、小节、隐藏、周期）+ 9 个节日小游戏 |
| 其他玩法 | 种地、采集 | 动物、钓鱼、烹饪、暗渠探索与战斗、匠作、收集馆、婚恋 |
| 对白与剧情文字 | 约 1 千字 | 约 25 万字（分批写入） |

诚实说明：这是一个需要分阶段连续推进的大工程。每一阶段都应该能独立运行、通过测试、截图验收，不留半成品。

## 2. 原创性约定

借鉴类型的“好玩的骨架”，不复制任何具体内容。这是明确的红线：

- **不使用**任何同类游戏里的人物、名字、台词、剧情桥段、地名、物品名与数值表。
- **不复制**其核心设定的结构：不设“继承爷爷的农场 + 公司与社区中心对立”的主线，不设“收集束修复社区中心”的任务；本作主线是**祖母的信 → 修复青苇镇的「六盏灯」 → 面对水库搬迁计划**。
- **不设**对应的小精灵/怪物系统。本作的超自然元素是“灯语”与“渡灯人”，见 01-world.md。
- 可以共有的是行业通用元素：四季、节日、好感度、送礼、婚恋、钓鱼、采矿类探索。这些是类型惯例，不是某一款游戏的专有内容。

## 3. 创作原则

1. **没有反派**。冲突来自“每个人都以为别人不在乎”和“外部力量不容易被说服”。水库搬迁计划的提出者也有他的道理。
2. **每个人是别人故事的一部分**。30 个人之间有约 60 条明确关系线，任何一位的事件都会牵动至少一位别人。
3. **每个角色携带一个玩法钩子**，让剧情与成长互相推动，而不是纯对话。
4. **玩家选择会留下痕迹**，但不惩罚：关键抉择改变对白、节日布景、结局的一段，不会让任何一条线卡死。
5. **日常是主体**。主线推进只占每季约三分之一的日子，其余时间留给种地、与人相处、探索。
6. **节制的感伤**。每个人的秘密都应当是日常可理解的（愧疚、舍不得、怕麻烦别人），不制造夸张苦难。

## 4. 路线图

按“能玩、能验收”的顺序分阶段。每阶段结束都跑 `make check`、`make test`，并截图。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 设计 | 本目录全部文档，确认后冻结 | 你确认角色、剧情、美术方向 |
| P1 美术管线与样张 | 建立逐像素手绘流程；先做 **一位角色的完整样张**（头像 3 表情 + 4 方向走路 + 待机），再做地形与建筑样张 | **你看过样张认可，才开始批量绘制** |
| P2 日历与季节 | 28 天四季、天气、生日、节日框架；**特殊事件框架**（触发条件、冷却、避让规则）；地形与作物按季节换装 | 四季循环存档可用；事件框架有测试 |
